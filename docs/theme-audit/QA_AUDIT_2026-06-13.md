# Nile Theme — Comprehensive QA Audit & Stabilization (2026-06-13)

Triggered by user-reported bugs found by accident after the Phase 1 live
switchover ("every dropdown opens at the top-left", "font looks too big",
"no customization controls"). Root-caused, fixed, and hardened with an
automated browser QA harness. Live DB: `erpmedsupply`.

## Defects found & fixed

### 1. Every dropdown opens at the viewport top-left (CRITICAL) — FIXED
- **Trigger:** only for users with **"Reduce motion" enabled at OS level**
  (macOS Accessibility → common). That's why scripted QA — which runs
  with no such preference — never saw it.
- **Root cause:** `nile_core/static/src/scss/motion.scss` shipped a
  reduced-motion guard `* { transition-duration: 1ms !important; … }`.
  `transition-duration` alone implies `transition-property: all`, so when
  core's positioning engine (`web/core/position/utils.js reposition()`)
  resets a popper to `top/left: 0` and *synchronously* measures it via
  `getBoundingClientRect()`, the element is still mid-transition at its OLD
  coordinates. The solver then computes garbage offsets → every dropdown /
  datepicker / autocomplete lands at (0,0).
- **Fix:** the guard now only zeroes Nile's own motion tokens
  (`--nile-motion-fast/base: 0s`) + `scroll-behavior: auto`. Wildcard
  `transition/animation` overrides are now documented as forbidden
  (motion.scss header + TOUCHPOINTS.md hazard note).
- **Verified:** many2one, datepicker, user menu, cog menu, searchbar,
  navbar sections — reduced-motion on/off × chromium/webkit × 6 viewports
  (1920→390px) × EN/AR: all anchored correctly.

### 2. Font renders too large — FIXED
- **Root cause:** Alexandria has a tall x-height / wide glyphs; at core's
  14px base it reads like 15–16px. (The `--nile-type-*` scale in tokens.scss
  was designed for a 13px base all along.)
- **Fix:** `$o-font-size-base` → 13px (`nile_core/primary_variables.scss`),
  plus a per-user **Font size Small/Default/Large** control in the new
  configurator (html root-font-size scale: 15/16/17px → body ~12.2/13/13.8px;
  "Large" ≈ the old look for users who prefer it).

### 3. No customization controls (Spiffy parity gap) — BUILT: `nile_config`
Spiffy-style **top-menu configurator** (paint-brush systray icon → dialog),
fully usable by non-technical users, EN+AR (ar.po shipped):
- **Company theme** (admins only): 6 curated palette presets + custom color
  picker. Runtime `:root` CSS-var injection per the ratified plan — palette
  switch needs **no SCSS recompilation**; compiled brand surfaces (navbar,
  primary/outline buttons, links, checked inputs) are re-pointed at
  `var(--nile-color-brand-*)` by a bounded override sheet.
- **My preferences** (every user): font family (Alexandria/System), font
  size (S/M/L), density (comfortable/compact), chatter position
  (bottom/side — writes the adopted OCA `web_chatter_position` field).
- Live preview on click; Save persists (`res.users` self-writeable fields /
  `res.company` for admins) and reloads. Discard restores. Prefs also
  surfaced on the user Preferences form. Server injects the saved theme as a
  `<style>` in `webclient_bootstrap` → no flash of default theme.
- **Control count: 6** (hard cap 8 per plan §3.3).
- **Dark mode deliberately not exposed:** Odoo 18 *Community* ships no dark
  stylesheets (Enterprise does); enabling the `color_scheme=dark` cookie
  renders a broken half-light UI. Toggle lands in Phase 3 with a real Nile
  dark skin (`tokens.dark.scss` groundwork already shipped). The theme
  service keeps the cookie synced (i.e. forced light) so nobody can get
  stuck in the broken state.

## QA harness added (scripts/)
- `qa_matrix.py` — chromium+webkit × 6 viewports × 6 dropdown types,
  mis-position + JS-error detector.
- `qa_probe_widgets.py` — many2one/datepicker/kanban/command-palette probes,
  with and without `prefers-reduced-motion`.
- `qa_visual_sweep.py` — full-page EN/AR/login screenshots across the demo's
  main views + automated checks (horizontal overflow, broken images, font
  fallback, JS errors). Output: docs/theme-audit/qa/sweep/.
- `qa_test_nile_config.py` — 15-assertion functional test of the
  configurator (preview/save/persist/restore, admin + non-admin).
- `qa_probe_dropdown.py` — the original reproducer kept as a regression probe.

All green at audit close (0 failures, 0 JS errors). Endpoint security scan
(`check_public_endpoints.py`): PASS — 0 public routes outside whitelist,
all 46 Spiffy routes 404. `nile_config` uninstall→reinstall round-trip on
the spike DB: clean.
