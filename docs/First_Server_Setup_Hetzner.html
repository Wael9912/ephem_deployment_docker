Your First Customer on Hetzner

A beginner's step-by-step guide. No experience needed — just copy and paste.

What you'll have at the end: your medical-supply ERP running on the internet, with your first customer logged in at their own secure web address (e.g. https://acme.example.com).

Before you begin, get these 3 things:

1. A free Hetzner account  ·  2. A domain name (a web address — buy one for ~$10/year at Namecheap or Cloudflare)  ·  3. About 1 hour.

How to follow this guide. You'll type commands into a "terminal" — a black window where you type instructions. Copy each grey box, paste it in, and press Enter. Do them in order. Words in CAPITALS are things you must swap for your own details (see the table below). If anything fails, jump to "If something goes wrong" at the end.
When you see…Replace it with…Example
acmeYour customer's short name (lowercase, no spaces)sudanmed
example.comYour domain namemycompany.com
YOUR_SERVER_IPThe number Hetzner gives your server91.99.12.34
you@example.comYour email addressme@gmail.com
1

Rent the computer (the "server")

A server is just a computer you rent that stays on 24/7 in a data centre.

Go to console.hetzner.cloud, sign up, and create a New Project called medsupply. Then click Add Server and choose:

  • Location: Falkenstein or Helsinki (closest to Sudan = faster)
  • Image: Ubuntu 24.04
  • Type: CPX31 (4 CPU / 8 GB / 160 GB, about €14/month) — plenty for your first customer
  • SSH Key: click Add SSH Key. On your own laptop, open a terminal and run the line below, copy the whole result, and paste it into Hetzner:
# If it says "No such file", first run:  ssh-keygen -t ed25519  (press Enter a few times)
cat ~/.ssh/id_ed25519.pub

Create the server, then copy the IP address Hetzner shows you. That's your YOUR_SERVER_IP.

2

Connect your domain (web address)

This tells the internet that your web address should lead to your new server.

Log in to where you bought your domain, find the DNS settings, and add one A record:

TypeNameValue
AacmeYOUR_SERVER_IP

This makes acme.example.com point at your server. It can take a few minutes to an hour to start working.

Important: do this now and let it settle. Step 8 (the security padlock) will fail if the web address isn't pointing at the server yet.
3

Log in to the server & lock the doors

We connect to the server, then close every entrance except the ones we need.

On your laptop terminal, connect to the server (type yes if it asks to trust it):

ssh root@YOUR_SERVER_IP

Now you're on the server. Run these to update it and switch on the firewall:

apt update && apt upgrade -y
apt install -y ufw fail2ban git
ufw allow 22 && ufw allow 80 && ufw allow 443
ufw --force enable

This blocks everything except logging in (22), and web traffic (80 and 443).

4

Install Docker (the engine)

Docker is the engine that runs the ERP. One command installs it.

curl -fsSL https://get.docker.com | sh
docker --version   # should print a version number
5

Download the system

We copy your ERP code and add-ons onto the server.

git clone -b erp-deployed https://github.com/Wael9912/ephem_deployment_docker.git ephem-deploy
cd ephem-deploy
git clone -b v18.0.1.0.0 https://github.com/Wael9912/erpmedsupply-addons.git erpmedsupply-addons
git clone -b v18.0.2.5.1 https://github.com/Wael9912/odoo-nile-theme.git   odoo-nile-theme
If it asks for a username and password: your code is private. Go to github.com/settings/tokens, create a token (classic, tick repo), then use your GitHub username and paste the token where it asks for the password.
6

Set your two passwords

The system needs two passwords: one for the database, one "master" password for managing it.

First, make two strong passwords — run this twice and keep both results somewhere safe:

openssl rand -base64 24

a) The settings file. Open it:

cp .env.example .env
nano .env

Find the line starting with POSTGRES_PASSWORD= and put your first password after the =. Save with Ctrl+O then Enter, and exit with Ctrl+X.

b) The Odoo config. Open it:

cp odoo.conf.prod odoo.conf
nano odoo.conf

Change these four lines, then save the same way (Ctrl+O, Enter, Ctrl+X):

admin_passwd = your_SECOND_password
db_password  = your_FIRST_password
dbfilter     = ^%d$
list_db      = False
The most common beginner mistake: db_password here must be exactly the same as POSTGRES_PASSWORD in the .env file. Copy-paste it to be sure.

c) Prepare the web server:

cp nginx/default.conf nginx/active.conf
7

Switch it on

docker compose up -d
docker compose ps   # everything should say "Up" (the database says "healthy")

The first time, this downloads about 1 GB — give it a couple of minutes.

8

Add the security padlock (HTTPS)

This gives your site a free certificate so the address starts with a secure https://. It renews itself forever.

bash scripts/ssl-setup.sh acme.example.com you@example.com
9

Create your customer

One command builds the customer's database and installs everything — inventory, purchasing, sales, accounting, and your Nile theme.

bash scripts/new-tenant.sh acme acme.example.com you@example.com --no-ssl

When it finishes, open https://acme.example.com in your browser, log in as admin, and set a strong password right away. 🎉 Your customer is live!

Now follow the Customer Onboarding Checklist (the other PDF) to set up their company, users, products, and so on.

10

Turn on backups

This is medical data — never run without backups. This makes an automatic copy every night.

crontab -e   # if it asks which editor, choose nano (option 1)

Paste this line at the bottom, then save (Ctrl+O, Enter, Ctrl+X):

0 2 * * * cd /root/ephem-deploy && DB_NAME=acme bash scripts/backup_db.sh >> backups/cron.log 2>&1
One more step soon: copy those backups off the server too (e.g. to a Hetzner Storage Box or Backblaze B2). A backup that only lives on the same server is lost if the server dies. Ask for help setting up rclone when you're ready.

If something goes wrong

ProblemWhat to do
The website won't openRun docker compose ps, then docker compose logs --tail=30 odoo to see the error
The padlock (Step 8) failedYour domain isn't pointing yet. Run dig +short acme.example.com — if it doesn't show your server IP, wait and try Step 8 again
"Database not found"Normal until Step 9 finishes. After that, refresh the page
Login or database errorsThe two passwords don't match. Re-check Step 6: db_password = POSTGRES_PASSWORD

Adding your next customer (later)

Much quicker — just two things: add a new DNS A record (Step 2) for the new name, then run one command:

bash scripts/new-tenant.sh beta beta.example.com you@example.com

That one command handles the database, the security padlock, and the routing all at once.
